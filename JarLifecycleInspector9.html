JAVA 라이브러리 수명주기 점검

폴더 안의 JAR/WAR를 분석해 지원 종료(EOM·EOS·EOL), 보안 취약점(CVE)과 최신 버전을 확인합니다.

선택된 폴더 없음
점검 옵션
프로젝트 전체에 이 기간 동안 새 릴리스가 없으면 EOL로 추정합니다.
사용 중인 메이저 라인에 이 기간 동안 릴리스가 없고 더 새 메이저가 있으면 EOM으로 추정합니다.
준비 중
막대를 누르면 해당 상태만 표시합니다. 빗금은 릴리스 이력 기반 추정입니다.
상태 라이브러리 현재 버전 동일 라인 최신 최신 버전 최신 릴리스일 EOM
(유지보수 종료)		 EOS / EOL
(지원 종료)		 취약점 판정 근거 · 비고 파일
점검할 폴더를 선택하세요하위 폴더까지 포함해 .jar와 .war 파일을 모두 찾습니다. 파일은 내 PC에서만 검사하며, 외부 조회에는 SHA-1 해시와 라이브러리 좌표만 사용합니다.
용어와 판정 기준
EOM
End of Maintenance. 기능 개선과 일반 버그 수정이 끝난 상태. 보안 패치는 계속 나올 수 있습니다.
EOS / EOL
End of Support / End of Life. 보안 패치를 포함한 모든 지원이 끝난 상태. 교체 대상입니다.
공식 판정
endoflife.date에 등록된 제품(Spring, Spring Boot, Tomcat, Hibernate, Log4j, Jetty, Netty, Kotlin 등)은 해당 버전 라인의 공식 지원 종료일로 판정합니다. 이미 EOL이 잘 알려진 라이브러리(Log4j 1.x, Commons HttpClient 3.x, Jackson 1.x 등)는 내장 목록으로 판정합니다.
추정 판정
공식 데이터가 없는 라이브러리는 Maven Central 릴리스 이력으로 추정합니다. 기준 연수는 점검 옵션에서 바꿀 수 있습니다. 추정 결과는 참고용이며, 중요한 라이브러리는 공식 사이트에서 확인하세요.
라이브러리 식별
JAR 내부의 pom.properties를 우선 사용하고, 없으면 SHA-1 해시로 Maven Central을 조회하며, 그래도 없으면 파일명으로 추정합니다.
최신 버전
alpha·beta·RC·milestone·SNAPSHOT은 제외한 정식 릴리스 기준입니다. Guava의 -jre/-android처럼 변형이 있으면 같은 변형끼리 비교합니다.
